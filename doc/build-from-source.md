# Building CernVM-FS from Source

These are the steps to get from a clean Linux machine to an installed
CernVM-FS built from a git checkout.  Build dependencies are installed with
`ci/build_install_builddeps.sh`, which reads the real dependency lists out of
the packaging metadata, so it stays in sync with what CI and the packages use.

## Supported platforms

`ci/build_install_builddeps.sh` detects the package manager from
`/etc/os-release` and supports three families:

| Family | Package manager | Dependency source |
|--------|-----------------|-------------------|
| Debian / Ubuntu | `apt-get` (via `mk-build-deps`) | `packaging/debian/cvmfs/control` |
| RHEL / CentOS / Fedora / Rocky / Alma | `dnf builddep` | `packaging/rpm/cvmfs-universal.spec` |
| SUSE / openSUSE | `zypper` | `packaging/rpm/cvmfs-universal.spec` |

Anything else fails with `Unsupported platform: cannot detect package manager`.
Run `ci/build_install_builddeps.sh --list` to print the dependency list without
installing anything.

## Build

```bash
# 1. Source
git clone https://github.com/vvolkl/cvmfs.git
cd cvmfs
git checkout <branch>

# 2. Build dependencies — the script calls sudo itself, so do NOT prefix it.
#    It installs the distro build deps and bootstraps cmake/go if the system
#    versions are too old (cmake >= 3.24, go >= 1.24).
ci/build_install_builddeps.sh

# 3. Put the bootstrapped cmake/go on PATH. Both scripts short-circuit and just
#    echo the system path when it is already new enough, so this is always safe.
eval "$(ci/bootstrap_cmake.sh)"
eval "$(ci/bootstrap_golang.sh)"
export PATH="$CVMFS_CMAKE_DIR:$CVMFS_GO_DIR:$PATH"

# 4. Configure
mkdir -p build && cd build
cmake -DCMAKE_BUILD_TYPE=RelWithDebInfo ..

# 5. Build. The first run also builds the vendored externals (openssl, curl,
#    sqlite, ...), so expect this one to take a while.
make -j"$(nproc)"

# 6. Install. Default prefix on Linux is /usr, not /usr/local.
sudo make install
```

## Choosing what to build

On Linux the defaults already cover the client, the server tooling and the
receiver.  The Go components are opt-in:

| Option | Default (Linux) | Builds |
|--------|-----------------|--------|
| `BUILD_CVMFS` | ON | FUSE client |
| `BUILD_SERVER` | ON | `cvmfs_server`, `cvmfs_swissknife` |
| `BUILD_RECEIVER` | ON | `cvmfs_receiver`, used by the gateway |
| `BUILD_LIBCVMFS` | ON | client library |
| `BUILD_GATEWAY` | **OFF** | `cvmfs_gateway` (needs a Go compiler) |
| `BUILD_DUCC` | **OFF** | `cvmfs_ducc` (needs a Go compiler) |
| `BUILD_UNITTESTS` | **OFF** | `cvmfs_unittests` for `ctest` |

So a branch that touches the gateway needs it turned on explicitly:

```bash
cmake -DBUILD_GATEWAY=ON -DCMAKE_BUILD_TYPE=RelWithDebInfo ..
```

and to run the unit tests afterwards:

```bash
cmake -DBUILD_UNITTESTS=ON -DCMAKE_BUILD_TYPE=RelWithDebInfo ..
make -j"$(nproc)"
ctest -VV                              # runs cvmfs_unittests, minus *Slow
./test/unittests/cvmfs_unittests --gtest_filter='*CatalogMgr*'   # or directly
```

`BUILD_ALL=ON` turns on the client, server, libraries, shrinkwrap, preloader
and unit tests in one go, but still not the Go components.

## Notes

- **Install prefix.**  `CMAKE_INSTALL_PREFIX` is forced to `/usr` on Linux
  rather than the CMake default of `/usr/local`, because the mount helpers and
  config files have to land in `/etc` and `/sbin` to be found.  Configuring
  with `/usr/local` anyway produces a warning and a probably non-working
  installation.
- **Externals.**  `BUILTIN_EXTERNALS` is ON by default: the third-party
  libraries are built from `externals/` into `externals_install.<arch>` (plus a
  `.<distro>` suffix when the distro is detected) instead of being taken from
  the system.  This is what makes the first build
  slow; later builds reuse it.  Set `BUILTIN_EXTERNALS=OFF` to link against
  system libraries instead.
- **`compile_commands.json`** is generated by default (the top-level
  `CMakeLists.txt` sets `CMAKE_EXPORT_COMPILE_COMMANDS` before `project()`), so
  clangd and `clang-tidy -p build/` work with no extra flags.
- **Rebuilding after a pull** only needs `make -j"$(nproc)"` from `build/`;
  CMake re-runs itself when the build files change.
